# 手羽屋 出店先運用ルール仕様書

**最終更新**: 2026-05-02
**対象システム**: tebaya-report シフト推奨エンジン

このドキュメントは、シフト自動生成エンジンが各出店先をどう扱うかを定義します。実装は `lib/shift-config.ts` および `lib/shift-engine/` 配下に反映されています。

|マンガ倉庫|1店舗       |✅ する（土日のみ）|自由出店  |土日優先・月初+3点         |

## 2. ながやま系（自動配置）

### 対象6店舗

|店舗 |スコアリングランク|月次目標|土日比率上限       |特殊制約                            |
|---|---------|----|-------------|--------------------------------|
|三股店|C        |8日  |30%          |—                               |
|鷹尾店|A        |7日  |55%          |土日に集中投入                         |
|若葉店|C        |6日  |40%          |—                               |
|志比田|C        |5日  |40%          |名前は「志比田」、表示は「ながやま志比田店」          |
|山田店|C        |5日  |30%          |—                               |
|都北店|C        |4日  |100%（事実上制約なし）|**火/木/日 ソフト制約**（+30点 / 他曜日 -20点）|

※ STORE_RANK は PDFスコアリング用の重み（locations.rank とは別概念）

### 申込フロー

1. ながやまから2ヶ月に1度、PDFスケジュール表が届く
1. PDFには各店舗×各日に「手羽屋」「他業者名」「空欄」が記載
1. 「手羽屋」と書かれた日 = **確定日**（既に押さえてある）
1. 空欄 = **空き枠**（手羽屋が応募可能）
1. エンジンが空き枠から推奨選定し、月次目標を満たす日を提案
1. ユーザー確認後、ながやま大田原様（food-assistant@m-nagayama.co.jp）へメール送信

### スコアリング式

ベース 100点 から以下を加算：

```
全店共通:
  祝日       +30
  20日/30日  +15

ランクA（鷹尾店）:
  土日       +50
  祝日       +20（共通の+30に追加）
  平日       -10

ランクB:
  土日 or 祝日  +30

ランクC（その他5店舗）:
  土日       +10

都北店のみ追加（NAGAYAMA_DAY_PREFERENCE）:
  火/木/日   +30
  その他曜日 -20
```

### 制約の優先度

#### ハード制約（確定日には適用しない）

|ID|制約              |違反時の挙動           |
|--|----------------|-----------------|
|H1|同日に同一ながやま店舗の重複禁止|推奨選定で弾く（確定日同士は許容）|
|H3|4日連続出店禁止        |推奨選定で弾く          |
|H4|同店舗で同一週内2回まで    |推奨選定で弾く          |
|H5|土日比率上限超過禁止      |推奨選定で弾く          |

**重要**: 確定日（PDF発の決定）はハード制約を**全てスキップ**する。例えば三股店で確定日が同一週に5回あっても、シフトには含めて警告のみ出す。

#### 第2フォールバック

第1ループで目標未達の店舗があれば、**H1とH3だけに緩和**して再度埋める。それでも未達なら警告のみ。

## 3. マンガ倉庫（土日のみ自動配置）

### 配置ルール

- **MANGA_SOUKO_WEEKEND_ONLY = true**
- 月次目標: 8件
- 土日のみ候補
- 1日最大2店舗の制約は維持（既にながやま2店舗ある日には入らない）

### スコアリング

```
土日       +10
月初7日まで +3
```

### 平日に配置しない理由

平日のマンガ倉庫は売上が見込めない。エンジンで自動配置すると、じゅんさん（マンガ倉庫担当）が月水金不可なため【スタッフ要設定】が大量発生する副作用もあった。

### 将来の見直し可能性

平日にも出したくなった場合は、`shift-config.ts` の `MANGA_SOUKO_WEEKEND_ONLY = false` に変更すれば全曜日対象に戻せる。

## 4. イオンモール都城駅前（手動配置）

### なぜ自動配置しないか

- メール申込で空き状況に応じて出店枠が変わる
- 「火曜市」「20日/30日（5%OFF）」「祝日」など特定日に集中したいが、
  これは「枠がある場合」の話
- 自動配置するとじゅん月水金問題で未割当が増える副作用

### 運用方法

- ユーザー（じゅんさん）が UI から日付・店舗を手動指定して追加
- スタッフはじゅん固定（自動割当）

### 高価値日（手動追加時の参考）

|曜日/日付|理由   |
|-----|-----|
|火曜   |火曜市  |
|20日  |5%OFF|
|30日  |5%OFF|
|祝日   |来客増  |

## 5. パシオ系（手動配置・将来自動化検討）

### 4店舗と優先順位

|順位|店舗     |locations.id|申込|
|--|-------|------------|--|
|1 |パシオたかお店|15          |電話|
|2 |パシオ高城店 |8           |電話|
|3 |パシオ志比田店|16          |電話|
|4 |パシオ早鈴店 |—           |電話|

たかお店が最優先。たかお店で埋まらなかった分を順番に他店舗で補完する想定。

### 申込フロー（電話のみ）

- 各店舗の店長と直接電話交渉
- 関係性ができていれば希望日に入りやすい
- メール・自動連絡は対象外

### 現状：自動配置しない理由

- たかお店の出店実績がまだない
- 売上ランクが未確定（実績データがたまるまで）
- 将来 ランクC以上 が確定したら自動配置候補に再追加検討

### 将来の自動化条件（メモ）

```
たかお店のランクが C以上 と判定された時点で、
shift-config.ts の EXTRA_STORE_TARGETS に
"パシオたかお店": N を追加する。

その際の配置ロジック：
  1. たかお店を最優先で月X日配置
  2. 達成できなかったら高城店、それでもダメなら志比田店、早鈴店の順
  3. 全店舗とも、じゅん固定（電話交渉時にじゅんが店長と直接話す）
```

## 6. ニクルの朝市（手動配置）

### なぜ自動配置しないか

- 主催者がいるイベント
- 出店者は事前に決まっている
- 手羽屋が「行きたい」と言って即出店できる場ではない
- 主催者から声がかかった時のみ参加

### 運用方法

- ユーザーが UI から日付指定して手動追加
- 日曜固定（朝市は日曜開催）
- スタッフはかずき固定が基本（じゅんは他店舗の可能性高い）

## 7. スタッフ割当ルール

### 基本ルール（STAFF_ASSIGNMENT_RULES）

|店舗カテゴリ  |月曜 |火曜 |水曜 |木曜 |金曜 |土曜 |日曜 |
|--------|---|---|---|---|---|---|---|
|ながやま系   |なぎさ|かずき|イデ |かずき|かずき|かずき|かずき|
|マンガ倉庫   |じゅん|じゅん|じゅん|じゅん|じゅん|じゅん|じゅん|
|イオン（手動時）|じゅん|じゅん|じゅん|じゅん|じゅん|じゅん|じゅん|
|パシオ（手動時）|じゅん|じゅん|じゅん|じゅん|じゅん|じゅん|じゅん|
|朝市（手動時） |—  |—  |—  |—  |—  |—  |かずき|

### スタッフ曜日制約（STAFF_WEEKLY_PATTERN）

```
[月, 火, 水, 木, 金, 土, 日]  ※月起点
かずき: [○, ○, ○, ○, ○, ○, ○]  全曜日OK
なぎさ: [○, ×, ×, ×, ×, ×, ×]  月曜のみ
イデ:   [×, ×, ○, ×, ×, ×, ×]  水曜のみ
じゅん: [×, ○, ×, ○, ×, ○, ○]  火木土日のみ
```

### 競合検出と未割当処理

#### チェック1: 同人重複

同じスタッフが同日に2店舗担当 → **後から割り当てた方を null**、`note = "【スタッフ要設定】"`

優先順位（先に確定）: ながやま > マンガ倉庫 > イオン > パシオ > 朝市

#### チェック2: 曜日不可

`STAFF_WEEKLY_PATTERN[staff][weekdayJp]` が false なら **null + note** 付与

例：日曜のマンガ倉庫にじゅんがアサイン → じゅん日曜OK → 確定
例：月曜のマンガ倉庫にじゅんがアサイン → じゅん月曜不可 → 未割当

ただし**修正後はマンガ倉庫が土日のみなので、このケースは発生しない**。

### スタッフフォールバックは入れていない

「じゅん不可日にかずきへ自動転送」は実装していない。理由：

- 自動配置店舗をマンガ倉庫(土日のみ)に絞った結果、じゅんが困るシーンがほぼ消えた
- 残った未割当は同日多店舗確定（PDF由来）で、自動転送できる類ではない

## 8. note カラムの値ルール

|ケース            |note の値      |表示UI |
|---------------|-------------|-----|
|ながやま系（確定枠）     |`null`       |確定マーク|
|その他自動配置（マンガ倉庫等）|`"【未確定】"`    |未確定タグ|
|スタッフ未割当（競合発生）  |`"【スタッフ要設定】"`|赤色警告 |

優先順位：「【スタッフ要設定】」が「【未確定】」より優先。

## 9. 警告メッセージのカテゴリ

シフト生成時に出る警告と、その意味：

|警告カテゴリ    |例                   |対応            |
|----------|--------------------|--------------|
|目標未達      |「鷹尾店: 目標7日に対し選定3日」  |PDF空き枠不足。受け入れる|
|確定日制約違反   |「三股店: 確定日が同一週に5回」   |PDF発の現実、警告のみ  |
|都北店ソフト制約違反|「都北店: 火木日以外への割当 X日」 |PDF空き次第、許容    |
|マンガ倉庫不足   |「マンガ倉庫: 目標8件に対し配置7件」|土日が他店舗で埋まった   |
|スタッフ未割当   |「5/4: 同日重複でスタッフ要設定」 |UI で手動補正      |
