# 日報の選択肢を店ごとに分ける（kp42）

2026-09-19 司令室B

## 何が困っていたか

経理パッケージを申し込んだお店が日報を打つと、選択肢が手羽屋のままだった。

- 出店場所 … 「ながやま三股」「PASIO高城」から選ぶことになる
- 担当者 … 「イデ」「じゅん」から選ぶことになる
- 商品と単価 … 「手羽先 200円」から選ぶことになる

逆に、そのお店が自分の会場や商品を足すと、**手羽屋の日報の選択肢にも並ぶ**。
どちらも「払ったのに使えない」につながるので、送る（kp24）の前に直す必要があった。

## どう直したか

日報そのものと同じ考え方（kp35）をそのまま使った。

1. 選択肢の3つの棚（`locations` / `staff_members` / `sale_products`）に
   「どの店のものか」の欄（`tenant_id`）を1つずつ足す。**空（null）＝手羽屋**。
2. これらを読む所すべてに「開いているお店のぶんだけ」の絞り込みを付ける
   （`applyTenantScope` … `lib/tenantScope.ts`。工事の取りこぼしは検算で見張る）。
3. 選択肢を足す所（管理者ページの3つのマスタ・日報の「商品をその場で足す」）では、
   いま開いているお店の印を付けて保存する。
4. 手羽屋のスタッフ名の保険の一覧（コードの中の `STAFF_OPTIONS`）は、
   **手羽屋のときだけ**出す。よそのお店では自分で登録した担当者だけが並ぶ。

## 手羽屋はどうなるか

**1行も書き換えていない。** いまある出店場所・担当者・商品はすべて印が空なので、
「印が空のものだけ」に絞った結果はいまと同じ。
これから手羽屋が足す行も印は空のまま。見えるものも保存される中身も今までどおり。

## 申し込んだお店は、どうやって選択肢を登録するか

**追加の画面を作らずに済む形にした**（画面を増やさないほうが壊れにくいため）。

| 選択肢 | 登録のしかた |
|---|---|
| 出店場所 | 日報 STEP1 の「その他（自由入力）」でその場で打つ |
| 担当者 | 日報 STEP1 の「その他（手入力）」でその場で打つ |
| 商品と単価 | 日報 STEP4 の「商品をその場で足す」から登録（そのお店の印が付く） |
