# お申し込みが本当に人に届くかを、本番で実測した（2026-09-19・kp60）

## 何をしたか
本番のお申し込みフォーム（https://tebaya-report.vercel.app/keiri/apply ）の受け口へ、
中身がはっきり分かるテストの申し込みを1件送って、**人に届くか**を確かめた。

## 分かったこと（実測）

| 調べたこと | 結果 |
|---|---|
| お申し込みの受け口（POST /api/keiri/apply） | **503。「いま受け付けができませんでした」** |
| スタッフLINEへの知らせ | **届かない**（`/api/line/diagnose?send=1` → `429 Too Many Requests`） |
| 倉庫（keiri_applications）への控え | **残らない**（サーバー側の鍵が壊れているため／kp54・kp55） |

**429 の意味＝今月ぶんの「送れる数」を使い切っている。** LINE の送信数は月ごとに決まっていて、
毎月1日に戻る。つまり **9月いっぱい、スタッフのLINEには1通も届かない。**
※これは経理パッケージだけの話ではなく、**手羽屋の日報・設営後チェックの知らせも同じく届いていない**
（送る仕組みは1つだけなので）。※お金の出る話（プランの引き上げ）はこちらでは触らない。

つまり **9/19 05:40 の時点で、申し込みは入っても誰にも届かない状態だった。**
じゅんが下書き8通を送ったあとに店主が申し込んでも、気づけないまま消えるところだった。

## どう直したか（この実行で本番に出したもの）

1. **フォームが行き止まりにならないようにした。**
   知らせも控えも通らなかったとき、これまでは赤い字で
   「いま受け付けができませんでした。メールでご連絡ください」と出るだけだった。
   これを、**入れてもらった中身がそのまま入ったメールの下書きを開くボタン**に変えた。
   店主は押して送信するだけでよく、打ち直しは要らない。
   メールが開かない人のために、同じ文を貼り付け用に出し、電話番号も添えた。
   入力画面に戻っても、入れた中身は消えない。
2. **外から見て分かるようにした。** 診断（`/api/keiri/diagnose`）に2つ足した。
   - `notify` … スタッフLINEへ届くか（合言葉・送り先・**今月あと何通送れるか**）
   - `application_delivery` … 知らせと控えを合わせて、**申し込みが人に届くか**の1つの答え
   ※確かめるのに **LINE は1通も送らない**（送ると、その1通ぶん残りが減るため）。
3. 受け口は、入力の間違い（400）と届けられなかった（503）を `reason` で言い分けるようにした。
   画面はこれを見てメールの下書きに切り替える。

## 触っていないもの
手羽屋の日報・シフト・レジ・LINEの送り方（`lib/line/sendMessage.ts`）・お金の計算は1行も変えていない。
変えたのは `lib/keiri/` と `app/keiri/apply/` と `app/api/keiri/` だけ。

## 残っていること
- **kp55（Vercel の SUPABASE_SERVICE_ROLE_KEY を貼り直す・2分）**が済めば、控えが残るようになり、
  LINE が届かない今月のあいだも申し込みが消えない。
- LINE の月の送信数は **10月1日に戻る**。それまでの受け口は「控え」と「メールの下書き」の2本。
