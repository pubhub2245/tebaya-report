# 経理パッケージ：月3,000円 → 月15,000円（税込）に改定し、中身を広げた

作成：2026-09-18 司令室B（kp40・kp41）
じゅん決定：2026-09-18（チャット）「経理は月15,000円」

## 1. なぜ値上げしたか

月3,000円では、月10万円に届くのに **33軒** 必要だった。営業をしない（じゅんが売り歩かない）
前提では到達しない数字。15,000円なら **7軒**。

置きどころは「記帳代行の相場（月1〜3万円）の下側で、会計ソフトより上」。
改定した時点の申込は **0件** なので、既存のお客さんへの影響は無い。

## 2. 値段だけ上げない（kp41）

「道具を貸す 月3,000円」から「毎月の締めまでやる 月15,000円」に中身を広げた。
渡すものを4つに定義し、`lib/keiri/offer.ts` の1か所にだけ置いた。

| # | 渡すもの | 手を動かすのは |
|---|---|---|
| ① | 毎日の数字が出るアプリ（今月の利益・今の現金・まだ払っていないお金） | お店（日報を書く） |
| ② | 毎月の締め（1枚の要約＋会計ソフト用CSVを月はじめにお出しする） | こちら |
| ③ | レシートの取り込みと仕分け（怪しい読み取りはこちらで直す） | こちら |
| ④ | 聞かれたことに答える窓口 | こちら |

②〜④はすべて設計側（Claude）が手を動かす作業に限定してある。**運営者の稼働は増えない。**

渡さないものも同じ場所に書いた（`KEIRI_OFFER_NOT_INCLUDED`）。
- 税務の個別判断はしない（CLAUDE.md 5-2。お出しする科目は税理士さんへの下書き）
- 確定申告そのものの代行はしない
- 請求書払い・売掛が多い業態は現金中心の集計と合わない

## 3. 表示と請求が食い違わないようにした（ここが一番大事）

価格を上げると、**ページに「月額15,000円」と出ているのに、押すと3,000円で決済される**
という事故が起きうる。Stripe の支払いリンクは Vercel の環境変数に入っていて、
コード側からは金額が見えないため、気づけない。

そこで **支払いリンクを入れる環境変数の名前に金額を入れた**。

    NEXT_PUBLIC_KEIRI_PAYMENT_LINK  →  NEXT_PUBLIC_KEIRI_PAYMENT_LINK_15000

`paymentLinkEnvName()`（`lib/keiri/caseNumbers.ts`）が価格から名前を組み立てるので、
価格を変えると前の金額のリンクは **自動で見つからなくなり、ボタンは「準備中」に戻る**。
表示と請求が合わない恐れがあるなら、ボタンを出さないほうがよい、という考え方。

`tests/keiriCase.test.ts` に「3,000円のときのリンクが残っていても使われない」を固定した。

### そのため、いまの本番は「準備中」に戻っている

Vercel に入っているのは3,000円の支払いリンク（前の名前）なので、
申し込みボタンは出ず「申し込み受付は準備中です」と出る。これは意図どおり。

行き止まりにしないため、その下に **届く宛先（特商法の表記と同じメール）を1つだけ** 出した。

**戻すのに必要な作業（Stripe と Vercel の画面操作・司令室 kp40②）**
1. Stripe で「経理パッケージ（1店舗・月額）￥15,000/月」の商品と支払いリンクを作る
2. できたリンクを Vercel の Production に `NEXT_PUBLIC_KEIRI_PAYMENT_LINK_15000` で登録
3. 再デプロイすると、その瞬間に「申し込む」ボタンに戻る
4. `/api/keiri/diagnose` を開いて確かめる（未設定のときは上の手順を文章で返す）
