# 経理パッケージ「月15,000円で渡す中身」の点検（kp76）

2026-09-19 11:34　司令室B

## なぜこれをやったか

じゅんの指摘（2026-09-19）＝**「まだメールを送れるほど製品が出来上がっていない」**。
司令室はこれまで売り場（紹介ページ・お申し込みフォーム）ばかり直していて、
**売る中身そのものを一度も点検していませんでした。**

そこで、**手羽屋ではない「よそのお店」として**、本番のコードをそのまま動かして
1つずつ確かめました。結果を「動いた／動かない／そもそも無い」の3つに分けます。

---

## 結論（先に3行）

1. **計算そのものは動きます。**よそのお店の日報から、利益・手元の現金・未払いは正しく出ます。
2. **いまの本番では、申し込んだお店は1歩も進めません。**初回設定も、合言葉での入室も、
   必ず失敗します（サーバー側の鍵が壊れているため。kp55）。しかも受け皿の診断は
   **「お店の置き場：つながっています」と緑を出していました**（嘘の緑）。
3. **経費の科目わけが、よそのお店に対して手羽屋の対応表で行われていました。**
   汎用の対応表は作ってあるのに、どこからも使われていませんでした。

2と3はこの回で直して本番に出しました。

---

## ①日報を1件書ける

**動いた（ただし注意が1つ）。**

- 日報（`/report?s=<お店の番号>`）は、そのお店の印を付けて保存します。
- 出店場所・担当者・商品の選択肢も、そのお店のぶんだけ出ます（kp42 で工事ずみ）。
- 手羽屋の選択肢（ながやま三股・イデ・手羽先）は出ません。

注意：**日報の画面には合言葉がありません**（手羽屋も同じ作りで、現場のスタッフが
その場で開けるようにするためです）。お店の番号入りのリンクを知っている人なら誰でも
そのお店の日報を書けます。手羽屋では問題になっていませんが、よそのお店に売るときは
「このリンクは店内だけで共有してください」と伝える必要があります（→ kp77 の材料）。

## ②今月の利益が出る

**動いた。**

本番のコードをそのまま呼んで、よそのお店の日報2件（売上80,000円）で試した実測：

```
利益 41,600円（売上 80,000 − 経費 38,400）／日報 2件
```

## ③いまの手元の現金が出る

**動いた。**

```
手元の現金 107,600円（数え始め 50,000 ＋ 売上 80,000 − レジから払った経費 22,400）
```

## ④まだ払っていないお金が出る

**動いた（ただし中身は3つだけ）。**

```
まだ払っていないお金 16,000円（給与 16,000／外注費 0／家賃 0）
```

数えるのは **給与・外注費・家賃の3つだけ**です。仕入れの掛け（今月末払いの肉代など）は
入りません。これはもともとそういう作りで、手羽屋が全部現金払いだからです。
**「まだ払っていないお金が全部出ます」とは言えません。**売り文句を書くときは、
「給与・外注費・家賃のうち、まだ払っていない分」と正直に書くこと。

## ⑤手羽屋以外のお店として使える

**動かない（いまの本番では）。**　←　ここが今回いちばんの収穫

お店の置き場（`keiri_tenants`）には鍵（RLS）が掛かっていて、
**サーバー側の鍵でしか読み書きできません**。その鍵はいま壊れています（kp55。
中身が鍵ではなく日本語の文章）。鍵が使えないとき、読みに行っても
**エラーにならず「0件」が返ります**。そのため：

| お店がやること | 画面に出るもの | 本当の理由 |
|---|---|---|
| 初回設定のリンクを開く | 「このリンクは使えません」 | 0件が返る |
| 合言葉で経理画面に入る | 「パスワードが違います」 | 0件が返る |

＝**お金を払っても、1歩も進めません。**

しかも受け皿の診断（`/api/keiri/diagnose`）は、この状態で
**`shop_table: true`（お店の置き場：つながっています）**と出していました。
控え（`keiri_applications`）で同じ見落としを直したのに（kp57）、
お店の置き場だけ緑のまま残っていました。

→ **この回で直しました。**鍵が使えない間は緑にせず、
「申し込んだお店は初回設定も入室もできません」と理由つきで出します。

## ⑥経費の科目わけ（点検中に見つけたもの）

**そもそも無い（作ってあるのに、繋がっていなかった）。**

申し込んだお店の業態コードは `t_<お店の番号>` です。ところが対応表の一覧には
`tebaya` と `generic` しか登録されておらず、当たらないものは**手羽屋の対応表**に
戻る作りでした。＝**よそのお店の経費が、手羽屋の言葉で振り分けられていました。**

ふつうの飲食店にありそうな経費の言葉13個で実測：

| 使った対応表 | 雑費に落ちた（振り分けできなかった）もの |
|---|---|
| 手羽屋（いままで） | **6個** … 肉 仕入れ／野菜／小麦粉／パン／コーヒー豆／業務スーパー |
| 汎用（作ってあったのに未使用） | **2個** … パン／コーヒー豆 |

「肉 仕入れ」が仕入に入らず雑費に落ちる、という状態でした。

→ **この回で繋ぎました。**申し込んだお店は汎用の対応表を使います。
**手羽屋の業態コードは "tebaya" のままなので、手羽屋は1文字も変わりません。**
（残り：「パン」「コーヒー豆」は汎用の対応表にまだ言葉がありません。
「パン」は「フライパン」に当たってしまうので、安易に足すと逆効果です。
実際のお店の経費の書き方を見てから足すこと。）

---

## この点検から出た「次に作るもの」

1. **サーバー側の鍵を直す（kp55）。**これが直るまで、誰が申し込んでも使い始められません。
   お試し版（kp75）を作っても、本番の申し込みはここで止まります。
2. **お店が自分で使い始められる形（kp77）**に、次の2つを入れること。
   - 日報のリンクの扱い（合言葉が無いので、共有の仕方を案内に書く）
   - 「数え始めの日・手元の現金」を入れ直す道（初回設定でつまずいたときの逃げ道）
3. **売り文句の直し**：「まだ払っていないお金」は給与・外注費・家賃の3つだけ、と正直に書く。
