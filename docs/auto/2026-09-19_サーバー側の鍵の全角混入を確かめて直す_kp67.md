# サーバー側の鍵の全角混入を、確かめられる範囲だけ直す（2026-09-19・kp67）

## 何が困っていたか

Vercel（サイトが動く場所）に登録してある `SUPABASE_SERVICE_ROLE_KEY`
（倉庫のいちばん強い鍵）の値に、全角の文字が混ざっている（kp54 で実測）。
通信の合言葉には半角しか入れられないので、この鍵を使う処理が全部止まっていた。

止まっているもの3つ：

1. お申し込みの控え（`keiri_applications`）が1行も残らない
2. サイトに来た人の数（`site_visits`）が1件も記録されない＝見る数字3つのうち「訪問」が永久に0
3. 手羽屋の毎日のデータの控え（バックアップ）が取れていない見込み（CLAUDE.md 4-6）

正しい直し方は、じゅんが Vercel の画面で値を貼り直すこと（kp55・2分）。
ただし**その2分を待つあいだ、記録は1件も残らない**。
とくに今月は、申し込みの知らせに使う LINE の残りが**あと5通**しかなく
（手羽屋の日報の知らせと同じ枠なので、すぐ尽きる）、
LINE が尽きたあとに控えも残らないと、申し込みが**黙って消える**。

## やったこと

全角が混ざっているだけなら、**決まりどおり半角に置き換えて**使えるようにした。
ただし置き換えただけでは使わない。**鍵の形をしているかを確かめてからでないと使わない。**

確かめること（1つでも外れたら「直せなかった」扱い）：

- `.` で3つに分かれ、どれも半角の英数字と `- _` だけでできている（JWT の形）
- 真ん中を読むと JSON になり、`role` が `service_role`
- その中の `ref` が、いま繋ぎに行く倉庫の名前（`vtuyebyjbvjmucqpkxug`）と一致する

全角→半角の置き換えは JIS の決まりで1対1に決まっている変換（NFKC）なので、
こちらの推測は1文字も入らない。**鍵を推測で作り変えることは、絶対にしない。**

## 手羽屋が今より悪くなることは無い

直した鍵を使うのは、**いまどのみち動いていない所だけ**：

| 場所 | いまの動き | 直したあと |
|---|---|---|
| `serviceClientOrNull()` | 必ず `null`（＝何もできない） | 直せたら使う。直せなければ今までどおり `null` |
| `/api/hit`（訪問を数える） | 通常の鍵で断られる | 合鍵が使えるならそちら。だめなら今までどおり |
| `/api/keiri/diagnose` の読み取り | 通常の鍵 | 同上（＝直した鍵が本当に通るかの実地の確かめになる） |
| `serverClient()`（手羽屋の画面・シフト・LINE） | **1行も変えていない** | **1行も変えていない** |

万一この直しが外れても、倉庫側が断るだけで、いまと同じ結果（記録が残らない）で済む。

## 診断に何が出るか

`/api/keiri/diagnose` の `server_key` に `repaired` が出る。

- `repaired: true` … 全角を直して使えている。記録は残る。**それでも貼り直しの案内は消さない**
- `repaired: false` かつ `usable: false` … 直しても鍵の形にならなかった
  ＝**値そのものが違う**。使えない文字が何個あり、そのうち何個が半角に直せるかも出す
  （鍵の値そのものは、これまでどおり絶対に出さない）
