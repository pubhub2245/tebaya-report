# 経理パッケージ：お申し込みフォーム（/keiri/apply）

2026-09-19 司令室B ／ kp50

## なぜ作ったか

紹介ページ（`/keiri/case`）の申し込み枠は、**カード決済のリンクが設定されているときだけ**
「申し込む」のボタンを出す作りになっている（`lib/keiri/caseNumbers.ts` の `paymentLinkUrl()`）。

9/18 に価格を月15,000円へ改めたとき、設定値の名前に金額を入れた（前の金額のリンクが
そのまま使われる事故を防ぐため）。そのため **いまの本番は「申し込み受付は準備中です」と出ている。**

このあと じゅん が知り合いの店主3軒に紹介の URL を送る（kp24）。
送られた店主が開いて最初に見るのが「準備中」では、**一番大事な最初の1件がそこで終わる。**

Stripe と Vercel の画面操作（kp45・kp27②③）は司令室の環境からはできない。
そこで、**カードの受付口が無くても「申し込みます」と言える道を1本だけ**用意した。

## 何を作ったか

| もの | 場所 | 中身 |
|---|---|---|
| 考える部分 | `lib/keiri/apply.ts` | 入力の確かめ・整え、知らせの本文づくり。通信は書かない |
| 受け口 | `app/api/keiri/apply/route.ts` | 知らせ（LINE）と控え（倉庫）の2つに届ける |
| 画面 | `app/keiri/apply/page.tsx` ＋ `ApplyForm.tsx` | 入れてもらうのは4つだけ |
| 控えの棚 | `supabase/migrations/keiri_applications.sql` | **新しい表を1つ足すだけ**（既存の表は触らない） |
| 検算 | `tests/keiriApply.test.ts` | 11件 |

入れてもらうのは **お店の名前・お名前・メールアドレス・電話番号（任意）・ひとこと（任意）** の5つだけ。
多く聞くほど途中でやめられるので、折り返すのに要るものだけにした。
**この画面ではお金は動かない**（カード番号は入れてもらわない）。

## 届き方（どちらか片方でも通れば受け取れたことにする）

1. スタッフの LINE グループへ「申し込みが1件入りました」と知らせる
   （すでにある送り方 `sendLineGroupMessage` を**呼ぶだけ**。送り方そのものは変えていない）
2. 倉庫（`keiri_applications`）に1行控える

両方だめだったときだけ、画面に「メールでご連絡ください」と正直に出す（503）。
**黙って消える申し込みを作らない。**

### 順番の縛りが無い

`keiri_applications` の表がまだ無い間は、②だけが静かに失敗して①で受け取る。
SQL を流したあとは、何も直さなくても②も効き始める。
＝ **アプリを先に出しても、SQL を先に流しても、どちらでも壊れない。**
（kp38・kp46 のときのような「SQL が先、アプリが後」の受け渡しは要らない。）

## 紹介ページの変わり方

- カードのリンクが**無いとき**：「申し込み受付は準備中です」（行き止まり）→ **「申し込む」→ フォームへ**
- カードのリンクが**入ったあと**：今までどおり「申し込む」→ カード決済。
  その下に「カード以外でのお支払いをご希望の方はお申し込みフォームから」を小さく添える
- 価格の枠の「申し込みから使い始めまで、人の手は入りません」は、カードが無い間は事実でなくなるので
  「お申し込みのあと、担当からお支払いの方法をご案内します（通常1営業日以内）」に出し分ける

## 機械の書き込みよけ

人には見えない囮の欄（`website`）を1つ置いた。埋まっていたら機械と見なし、
画面には成功と同じ顔を見せて、**誰にも知らせない・控えない**。
